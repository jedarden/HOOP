Full output captured at `/tmp/hoop-test-full.log` (this session).

### The single compile error

```
error[E0432]: unresolved import `crate::integration_harness`
  --> hoop-daemon/tests/s2_transcript_archaeology.rs:22:12
   |
22 | use crate::integration_harness::spawn_test_daemon;
   |            ^^^^^^^^^^^^^^^^^^^ could not find `integration_harness` in the crate root
```

### Root cause

`hoop-daemon/tests/s2_transcript_archaeology.rs:22` writes
`use crate::integration_harness::spawn_test_daemon;` but **never declares the
module**. Every one of its 9 sibling integration-test files (e.g.
`state_projections.rs:27`) does it correctly:

```rust
mod integration_harness;                       // <-- declaration first
use integration_harness::spawn_test_daemon_…;  // <-- then use
```

The shared harness file exists at `hoop-daemon/tests/integration_harness.rs`
(52 KB), so the fix is almost certainly changing line 22 of
`s2_transcript_archaeology.rs` from `use crate::integration_harness::…` to a
`mod integration_harness;` declaration (matching siblings), or adding the `mod`
declaration. Note there is ALSO a duplicate copy at
`hoop-daemon/tests/acceptance/s2_transcript_archaeology.rs` — the top-level
`tests/s2_transcript_archaeology.rs` may be a stray/stale copy; a fix-bead
should reconcile the two.

## Supplementary recon — feature-gated code is also broken

The project's real test invocation is `make test`, which runs
`cargo test --lib --features testing` (see Makefile). To check whether enabling
the `testing` feature changes the picture, I ran a **compile-only** check
(`--no-run`, so no test subprocesses were spawned):

```
nix-shell -p pkg-config openssl --run \
  "cargo test --workspace --features hoop-daemon/testing --no-run"
→ exit 101
```

Result: **36 additional compile errors** appear once the `testing`-gated code
paths are activated:

- `hoop-daemon (lib)` — 5 errors
- `hoop-daemon (lib test)` — 31 errors

Representative errors (full list in `/tmp/hoop-test-feat-check.log`):

- Missing crates: `tempfile` (E0432/E0433), `rand` (E0433)
- Missing struct fields: `attachments_count` (PreviewRequest),
  `br_semaphore` + `br_semaphore_target_permits` (DaemonState),
  `accounts_file`/`gcp_quota_config`/`gemini_dirs`/`opencode_dirs`
  (CapacityMeterConfig), `stash_sha` (NeedleEvent), `bead_id` (CommitEntry),
  `draft_id`+`synthesis_result` (DictatedNote), `embedding`+`redaction`
  (HoopConfig)
- Missing fns: `ResolvedConfig::default`, `RedactionPolicyState::default`,
  `SecretPattern::default_secret_patterns`
- Signature drift: E0061 (function takes N args but M supplied),
  E0308 (type mismatch)

These indicate the `testing`-feature unit-test code has drifted substantially
out of sync with the current structs/source — i.e. the `testing` feature has
not been kept compiling. This is material for the CI-gate recon regardless of
which invocation the gate uses.
